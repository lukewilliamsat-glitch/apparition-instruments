# Admin V2.1 acceptance fixes

Baseline `6c833dbc298b0355ef5be89636572d3fff69126b`, tree `8a9c7b8cd852983221fc52a2697c67617d10ae97`.

Catalogue Settings deletion had a silent native `window.confirm` gate before the existing authenticated RPC. A false/suppressed prompt exited without feedback. Source inspection establishes that failure path, but cannot establish the browser-specific reason the human session did not display a prompt. Replaced it with an explicit labelled Admin dialog, safe Cancel focus, busy protection, and visible cancellation/error/success feedback. Existing `delete_unused_catalogue_option` persistence remains unchanged: Admin membership, manufacturer-only removal, Components/Kit Definitions dependency checks, row/table locks, no cascade; active or disabled references remain protected.

Safe row actions remain immediately available; less-common Settings and Inventory actions use native details/summary menus with Escape/focus support. Inventory retains its existing destructive confirmation and repository safeguards. Quiet scoped section typography, Overview area grouping and one primary shortcut, authoritative active/total counts, media metadata/technical identity and labelled decorative checkbox, local order summary/section anchors/empty tracking display, and Operations current-state/configuration headings address the acceptance findings. No changes to shell architecture, Orders list/domain, CMS, maintenance, Conjure, public source, backend contracts, dependencies or production data.

Focused tests use offline preload and fixtures. Luke performs rendered acceptance; automated checks do not establish visual acceptance.
