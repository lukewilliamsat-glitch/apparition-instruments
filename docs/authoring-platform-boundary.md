# Authoring platform boundary

The generic authoring primitives are document → section → block → content/properties, plus relationships outside body content, protected blocks, adapter-owned renderer, draft, preview, immutable revision and publication. `dist/authoring/document.mjs` depends on no Apparition modules, domain, visual identity, database or electrical model. JSON node paths and immutable replacement provide a bounded generic editing seam. This is an adapter contract, not a replacement of the accepted CMS model.

The Apparition CMS adapter projects existing body slots into the generic region registry. Private visual mode annotates the accepted rendered DOM, maps exact semantic regions and sends text patches through the existing ProseMirror transaction boundary. It has no published-row mutation path. Only headings/paragraphs with a single safe text run (or an empty paragraph) are directly editable; rich lists, tables and mixed formatting remain in the structured editor. Protected blocks are marked read-only and excluded from editable descendants. Stale canvas snapshots cannot overwrite a changed draft. Visual edits preserve node properties/source references and retain current save/preview/revision/publication semantics.

The accepted public renderer, styles, controller bindings, topology/electrical truth and Discovery nominations are adapter-owned and unchanged. Private annotations never enter static publication. No general page HTML editor is supplied.

Future seams: reusable section/block definitions, image/media references, responsive properties, bounded component configuration, section insertion, viewport preview and per-site renderer/data adapters. These require explicit contracts before expanding authoring authority. Multi-tenancy, domains, hosting, billing, generic commerce and external onboarding are not implemented. A future multi-site host would inject document/revision/media repositories, access checks and publication adapters; generic editing primitives must never import Apparition commerce or guitar models.

Media follows the same separation: generic metadata validation and draft-use concepts are in `dist/authoring/media.mjs`; Apparition-approved static paths, membership, tables, RPC transport and Admin presentation are adapters. Document word/reading metrics are generic. The public CMS renderer and protected source capsules remain Apparition-specific. No new generic primitive can import the adapter layer; deterministic boundary tests enforce this direction.

Repository interfaces (draft save, immutable snapshot creation, restore-as-new-revision, private preview and public projection) remain injected into authoring contexts rather than pulled into generic primitives. Future reusable section definitions would own a typed schema and properties; a per-site renderer would translate them. Responsive properties and viewport state require an explicit schema before editable layouts are introduced. No multi-site database, billing, hosting or commerce layer has been created.
