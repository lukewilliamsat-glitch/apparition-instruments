# Integration security boundary

Production entry uses the existing Admin Auth/membership gate. The new read service is inactive by default, has no URL or fetch implementation and accepts only an explicitly injected synthetic adapter in this engineering candidate. A real adapter cannot be enabled by query parameters. No production editor save/status, stock, image or private-cost method has an IO path. Synthetic writes require an explicitly supplied test persistence, syntheticOnly marker and syntheticWriteTesting flag; that fixture is never imported by dist.

Synthetic acceptance covers anonymous/nonmember denial, read-only and stock projections, finance-only catalogue denial, no private fields, no images/customer rows, invalid/partial responses, session revocation/expiry, stale in-flight responses, timeouts, safe retry and malformed detail identity. Retained draft owner mismatch conceals the workspace. Sign-out clears proposals and visible records before awaiting Auth logout. Synthetic capabilities are not a proposed live JWT role claim or evidence of real RLS.

Editor tests preserve inherited integer-pence validation, protected-field allowlist, draft/review/discard, stale detail/session handling, conflict and unknown-outcome semantics. In read-only mode even a programmatic save and manually enabled button submit no request. Unknown outcomes are exercised only against a labelled in-memory fixture with a committed receipt; no production success is simulated.

Unchanged legacy Admin writers and their broader membership model remain outside COMMAND's write path. Access to a legacy navigation label is not granular stock/finance permission or backend feature parity. Before deployment, separately establish the actual authoritative role contracts and verify private projections/permissions against the installed service. No Supabase request, auth.users/admin/customer/business row, token, SQL or migration was accessed. Native Chrome results follow the actual CI evidence, not this source-only report.
