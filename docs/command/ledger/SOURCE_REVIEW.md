## Findings that change this proposal

- Manual external Orders already exist in source; fees/profitability and audited item-amendment/value movements are separate gaps. Extend the existing Order identity and inventory transaction rather than creating a second order or a parallel editable quantity counter.
- A single nullable internal unit cost and a quantity balance cannot substantiate historical landed batches or frozen sale COGS. No acquisition-batch/WAC/value-journal contract was identified in the inspected production pathways. That is a source finding, not a complete deployed schema inventory.
- Existing assemblies use component capacity/consumption. Stocked finished products need an explicit build and mode cutover before sale, not a second invocation of the legacy BOM deduction.
- The legacy component/save/stock paths, shared paid-order inventory helper, external sales, assembly configuration and any unenumerated installed scripts/jobs must be reconciled. Source alone cannot identify all deployed or outside writers.
- Later external-order editing documentation adds explicit notification support beyond the earlier external-orders report. Preserve the current notification boundaries; LEDGER finance entry itself must not send email. Historical statements that a migration was once installed are not independent confirmation of today's database.
- IRONCLAD offers sound isolated transaction/receipt principles, not a deployed financial ledger, production auth adapter or schema migration. Its current single-product internalCost setter must not become an unjournalled valuation override.
