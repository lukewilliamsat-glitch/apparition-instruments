## Mobile workbench

The latent failure was a fixed `100dvh` body/main and `height:100%` workbench with hidden overflow. Later Circuit State and workbench chrome increased the content budget without relaxing those containers. Passing width-only DOM contracts did not establish canvas reachability.

The final experience stylesheet is loaded after the shared workbench/state styles. At widths through 850px, body, main, layout and workbench have explicit normal page flow, auto height and visible overflow. The diagram viewport alone has bounded scrollable space: `clamp(320px,60svh,620px)`, with a 320px floor. It remains in document flow whether secondary content grows or a device rotates. Signal Lab has normal page flow, rather than a second nested scrolling workspace. Desktop layout is retained.

Hierarchy is compact identity/navigation, graph-derived circuit caption, Circuit State and presentation controls, canvas, then secondary details/projects. The selector has short visual captions with complete accessible labels and the existing pressed state. All state remains owned by the existing graph/configuration adapters. Configure controls are the same DOM nodes moved into native dialogs; there is no second form or state model.

Configure and contextual Understand use native modal dialogs on phones, with obvious close controls, Escape, focus entry and return. A second sheet closes before another opens. Returning to desktop restores the same panels to their original placeholders. Selecting a component/terminal/conductor uses the existing Inspector engine. Opening inspection preserves zoom; its modal layer prevents confusing background interaction.

At Fit, vertical touch action permits document scrolling through the canvas region. Once magnified, pointer panning and existing two-pointer scaling operate within the viewport, without graph work or SVG replacement. Fit and 44px zoom controls remain available. Pinch starting from Fit is not a promised contract: browsers may consume/cancel a page-scroll gesture. Reliable Fit-start pinch and rendered gesture acceptance remain deferred to a deliberate device-tested follow-up. Pinch from the magnified workbench is covered by deterministic pointer math. No gesture dependency is added.

Forge, Generator, pickup configuration artwork and Inspector maps retain those exports. Electrical contacts and terminal positions remain inputs from existing graph authority; artwork contains no position/contact matrix.

The supplied lever/two-bank sketch and rejected production drawing were inspected as presentation references. The blade family is physically rebuilt with a cut-out metal spine/frame, mounting ears, central spindle/pivot, lever arm, two curved insulating/contact wafers, stationary contact fingers and formed solder tabs with apertures. Both banks and commons remain explicit. Trace/Explain wipers and engagement come only from the supplied closed pairs. Lever geometry remains monotonic with actual throw participation; intermediate positions are geometric midpoints. Build has fixed hardware and solder destinations without state overlays.

Pot shell cues, resistor bands, capacitor casing detail and output-jack hardware use the same restrained line/material vocabulary. Existing recognizable single-coil, humbucker and toggle artwork is reused. The established push/pull composition retains a pot and separately associated six-terminal DPDT section above it, with the original mechanical chassis links, two poles and unused-pole semantics. It is not electrically merged with the potentiometer. Existing treble-bleed circuits show their actual capacitor/resistor parts; no speculative assembly artwork or topology is added.

Hub snapshots are generated by `scripts/generate-component-illustrations.mjs` from actual existing graph component descriptors and the shared artwork. It runs locally at authoring time. No Hub graph/commerce dependency is introduced, no runtime network is required, and no additional production images are loaded. A deterministic equality contract prevents snapshots drifting. Hub detail is simplified using scoped styles; recognition is prioritized over micro-labels. Five existing educational studies remain, and the accepted editorial hierarchy/search/navigation is retained. Subtle background response and visible link focus respect reduced motion.

## Verification and limits

`experience-foundation-v1.mjs` validates all 13 blade states, frame/wafer/pivot/lug structure, both banks/commons, exact contact projections, five monotonic positions and P2/P4 midpoint geometry, Build state independence, source integrity and exact Hub snapshot generation.

`experience-foundation-v1-dom.mjs` loads the actual relevant CSS cascade and exercises widths 320, 360, 390, 412, 768, 1024, 1400 and 1920. It verifies normal-flow/visible-overflow ancestors, the usable canvas floor, panels and focus/Escape return, selector/split controls, modes, Fit/zoom, pan/scaling without SVG replacement, and Signal Lab state continuity. happy-dom's CSS parser requires whitespace after `@media`; fixtures normalize that grammar without changing rules. Its partial SVG geometry API is disabled in the shared DOM fixture because it cannot measure rendered artwork. These are explicitly structural/behavioural contracts, not screenshots or physical-device visual acceptance.

The existing browser fixture's Inspector expectation is updated to modal semantics; browser tests, browser installation, screenshots and rendered QA are not run in this pass. A single comprehensive final deterministic gate preloads the socket/fetch-blocking guard in all Node children. The previous module-loading, public-read, checkout/pricing and graph-equivalence safeguards are included.

Deferred: Guided Build V3, Component Passport, new switching/Signal Lab capabilities, account/QR infrastructure and 3D/digital twin work. Rendered desktop and mobile acceptance remain pending Luke.
