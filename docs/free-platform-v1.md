## A — evidence and implementation map

Forge already uses the shared instrument/configuration, response, terminal and
project authorities. Common instrument references, explicit unsupported states,
keyboard selection, responsive workbench modes, local projects and private-safe
share links exist. Preserve those authorities; add bounded editing history and
plain-language entry/export guidance around them.

Hub has six categories, an interactive landing, shared article rendering, a
published CMS projection, canonical metadata, schemas, sitemap and contextual
tool relationships. Discovery publication regenerates CMS-backed pages: additive
journeys must survive that render path, not merely patch generated HTML. Preserve
all existing interactions and article presentation.

Generator and Designer already consume shared circuit/project URLs. Handoffs must
remain capability-gated; unsupported circuit states must not acquire an invented
diagram, response, kit or commercial match.

Catalogue matches must derive from actual components and public catalogue truth;
unmatched requirements remain useful without a purchase claim. Stock and physical
fitment must remain separate from logical electrical compatibility.

Operations already has authoritative current-state RPC, scheduled transitions,
checkout enforcement, retained baskets and a public presentation adapter.
Catalogue/product Add controls are not yet consistently bound to that state.
Keep browsing and basket editing available; disable purchasing entry points while
closed or unavailable, without changing server contracts.

Announcements already reuse News publication/expiry/priority and scoped public
banner styling. Audit time boundaries and refresh independently of checkout.

No production project/data access is needed for the proposed frontend work.
Admin V2.1, Conjure V4, electrical authorities, homepage, account and backend
contracts are preservation surfaces. Use offline DOM/model tests and one final
integrated gate; rendered acceptance belongs to Luke.

## E — logical parts and conservative catalogue handoff

Forge derives each logical requirement from circuit components and preserves
unmatched requirements. Empty/descriptive arrangements explicitly have no complete
BOM. Only exact capacitor values and standard potentiometer resistance/taper can
produce individual catalogue suggestions. Unknown switch pinouts, pickups,
combined networks and physical fit are not inferred. Suggestions include out-of-
stock status and physical-fit warnings, never automatic purchases. Catalogue
lookup is explicit/on-demand and failure leaves the logical list available.

free-parts and the affected free-forge-workflow pass. Electrical, catalogue,
stock, price, basket and checkout authorities remain unchanged.

## F — purchase controls

One shared permission/binding primitive consumes the fresh Operations projection,
starts fail-closed and guards both UI state and click handlers. Components,
products, Kit Builder and Designer catalogue Add actions use it. Existing basket
kit edits remain distinct from creating a new basket selection. Price/stock
eligibility remains an independent constraint. Purchasing pages refresh on return
and schedule boundaries; tools and information remain usable on request failure.
Designer bindings are disposed before rerender to avoid listener accumulation.

free-commercial, kit-builder-dom holiday, holiday-checkout-basket and
operations-v2-isolated pass. These exercise OPEN, paused/unavailable, schedule
edges, preserved product information/configuration/baskets, direct checkout and
direct order RPC rejection with zero isolated order/stock side effects. Server
code, migrations, catalogue data and production state were not changed.
