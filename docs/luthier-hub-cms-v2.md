# Luthier Hub CMS V2 foundation

Supabase hub_articles is the private authoring authority; hub_article_revisions contains immutable published snapshots. Draft is separate from the current published revision. Stable UUIDs derive deterministically from the existing guide key, independently of slugs. New IDs are server-generated. Published slugs cannot change; no hard deletion or archive action is supplied. Optimistic edit_version prevents lost updates; per-slug transaction locks prevent collisions. Existing Discovery V2 primary nominations cannot be reassigned through this editor.

The seed is generated from the existing articlePage source renderer, with a byte comparison against all 22 accepted pages. No generated HTML is scraped as an independent authoring authority. A source-location adapter derives the editable semantic body and immutable presentation capsules from that renderer. Unchanged source blocks retain original bytes, classes, IDs and bindings; accepted bodies are not normalized into a new visual system. Source references are not author HTML. Diagrams, interactive modules, legacy tables and non-editor markup are protected atoms. Prose can be edited around them; new semantic tables can be edited with the table controls. Unlocking legacy technical tables requires a separate lossless adapter, not silent normalization.

The editor is ProseMirror, pinned and bundled as a standalone ESM module. It offers paragraphs, H2/H3, strong/emphasis/code, lists, links, new tables, technical notes, cautions, undo/redo. No font/colour/layout or executable HTML controls. Clipboard HTML is stripped to semantic content; unknown elements/attributes cannot enter publication JSON. Server validation also rejects unsupported nodes/attributes, unsafe links and unknown presentation references. Structured title, slug, category, introduction, SEO, indexability, intent and guide/tool/component relationships are outside body JSON. No raw schema editor is exposed.

Preview uses the same source-preserving renderer as static generation, in a private srcdoc iframe with noindex and no public draft URL. Only the existing trusted article scripts/styles and constrained body representation are included. No user scripts, iframes, styles or event attributes are accepted. The existing Admin gate authorises module loading; database membership checks and RLS independently authorise every mutation. The repository reads current ordinary Auth session tokens; no service-role key is shipped. Anonymous/non-Admin users cannot read authoring rows or history. The anonymous projection returns only current published content, not drafts, revision IDs, actors or timestamps of internal operations.

Publish validates, locks the article, creates an immutable revision, updates the published pointer and keeps the draft synchronized in one transaction. Restore reads an owned historical revision and creates a new publication with a new revision number. History is never modified. Public presentation remains static: the Pages job always reads the curated published projection, validates/stages all article outputs, then proceeds to artifact upload. Generation failure stops the job and leaves the previous live deployment intact. A successful Admin publish is committed content pending successful static generation, normally on the existing five-minute schedule, subject to queueing. No guaranteed instant publication is claimed. Uninitialised/unavailable CMS fails closed; it does not overwrite authored content with source seeds.

The CMS-only publication marker skips unrelated product/News/Operations snapshot generation. Future static-only pushes still refresh CMS published content so an older Git snapshot cannot replace authored articles. No new Edge Function is needed: transactional PostgreSQL RPCs provide the mutation boundary. Seed revisions have IMPORT action and no invented publishing Admin identity. Migration mutates only these two CMS tables and their deterministic existing-content seed.

Sitemap/indexability and Article/Breadcrumb metadata derive from structured fields. Existing search-intent families retain their nominated canonical pages; new articles are supporting content. Existing Hub landing and category presentation remain frozen. New articles have public static routes and sitemap discovery; contextual related-guide fields can connect them without redesigning the Hub. Adding cards to the frozen interactive landing is outside this pass. Preview/history inspection never alters a draft or public content.

## Future DOCX contract

DOCX ↔ structured body: Heading 2/3 ↔ H2/H3; bold ↔ strong; italic ↔ emphasis; lists ↔ semantic lists; tables ↔ article tables; links ↔ links; paragraphs ↔ paragraphs. Slug, category, SEO, schema, intent, publication and relationships stay structured, outside Word. Protected presentation capsules must remain identifiable during any future import/export. Import needs diff/change review, preview and an explicit draft/publish decision. The controlled DOCX implementation is described below. SEO/category/relationship fields remain outside Word.

## Explicit limits

Legacy technical blocks remain protected. Duplicate of a legacy presentation is deferred; create a new draft instead. Hard deletion, archive lifecycle, media upload, scheduled article publication and changes to Hub landing/category presentation are deferred. Publication date accepts a known historical date; unknown seed dates remain unknown until supplied. Updated date records each CMS publication. Electrical models/topologies and all commerce, Operations, News and eBay authorities remain unchanged.


## CMS editor UX and controlled DOCX workflow

The private library supports title/slug search, category/state filters and title/recent-save ordering. Imported publication pointers distinguish published guides from never-published drafts. Eleven legacy guides have no established publication date; their UI says Date not recorded, not Not published. Existing dates are displayed in en-GB, with timestamps in Europe/London. No date backfill is invented. Draft changes pending compares authoring content against its published snapshot. Related selections preserve ordering; search and explicit add/remove do not invent relationships. The disabled controlled intent selector shows only the current authoritative nomination or supporting-guide status; the server retains its fixed Discovery boundary.

The existing ProseMirror schema remains unchanged. Formatting controls are grouped into Text, Structure, Technical, Table and History; toolbar/canvas styles are private and scoped to data-hub-cms. Explicit Preview opens a private about:blank window containing the same sandboxed source-preserving preview; the inline preview is retained as a popup fallback. Preview creates no public route and neither saves nor publishes.

DOCX uses pinned fflate 0.8.3 for narrowly scoped ZIP creation/decompression and the native XML parser. No existing ZIP/DOCX adapter was present. The browser bundle is loaded only after an explicit DOCX action; no Office runtime, generic HTML importer or new editor framework is introduced. Export includes title/intro, paragraphs, H2/H3, strong/emphasis/code, lists, links, simple semantic tables and callout structures. Source bookmarks and visible Apparition-controlled structure boundaries preserve original source wrappers. Protected block markers contain the article UUID, body slot and stable source reference; technical source HTML is never placed into Word. A custom XML authority part records only article ID, edit version and body hash. No credentials, actor metadata or unrelated drafts are exported.

Import parses a maximum 5 MB DOCX, with bounded ZIP entry counts and 12 MB total expanded metadata. It rejects malformed packages, oversized parts, macros/embedded executable objects, unsafe XML declarations, unsafe links, external document relationships and mismatched export authority. It never fetches embedded resources. Word fonts/colours/layout are discarded. Images and unsupported constructs are explicitly reported for review. Tracked changes/content controls and merged/nested tables block import. External DOCX can supply supported prose to a simple unprotected draft; existing structured articles require an export from their current draft so source/protected markers remain authoritative. Generic nested external list levels are explicitly reported as flattened. Existing exported nested list structure is preserved by markers.

Removed, altered, duplicate, misplaced or forged protected/structure markers block acceptance. Valid markers resolve exclusively to current trusted article nodes; typed markers do not create new trusted technical content. Stale exports must be re-exported after the draft changes. Published content is never used as a mutable import destination. Public renderers, CSS, canonical/schema generation, Discovery and sitemap code remain unchanged.

The review lists headings, paragraphs, lists, tables, links, title/intro changes and protected-block status, plus ignored/unsupported content. Cancel makes no changes. Accept requires explicit acknowledgement and a current unchanged review base. It calls only save_hub_docx_import, never publication. That RPC checks authoritative Admin membership, optimistic edit version, unchanged intelligence and the complete per-slot protected-node identities before invoking existing DRAFT save in the same transaction. hub_article_draft_imports records an immutable private snapshot, DOCX_IMPORT provenance, actor and draft version. Anonymous/non-Admin users cannot read or mutate these snapshots. Existing published revision pointers, immutable history and restore-as-new-publication remain intact.

DOCX draft import history is separate from publication history. Editor draft saves use the existing draft/version model; successful publication and restore retain existing revision actions. There is no raw DOCX storage/upload endpoint or import-to-publish shortcut. Word application acceptance is Luke's manual step; no Office/browser/rendered QA was performed.

Deferred: images/media, merged/nested table editing, comments/footnotes/fields, automatic conversion of protected technical markup, archive/deletion and broader editorial lifecycle. Existing legacy technical tables stay protected. Unsupported content is reviewed explicitly, not silently promoted into public output.
