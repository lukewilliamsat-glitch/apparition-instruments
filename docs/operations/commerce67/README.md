# Commerce Ascendant acceptance and release gates

Base: NIGHTFALL application `afbac1358e782b588d222960eebb03f170a026bb`. Cloudflare production `7bfe4df0-02be-4bf2-9130-7e200be3688d`; pre-NIGHTFALL rollback `69e29ee3-e5e6-4101-a72e-4555ec18e593`. This branch is not a production release.

## Engineering

The existing Offers & Bundles studio remains a draft/rehearsal calculator. The saved editor adds audited versioned definitions, schedules and lifecycle, explicit eligibility and exclusions, quantity tiers, priority, stackable/exclusive rules, codes, bundles, compatible add-ons and measured CTS sets. Authenticated requests use the current Admin session; database RPCs independently require Admin membership. Direct table access is denied. Checkout-only and expiry mutation RPCs are service-only. The public projections return bounded terms/configurations and quoted prices, with no images, costs, exact stock counts or physical measurement identifiers.

The database prices a bounded basket from catalogue rows and server-owned rule versions. Currency is GBP in integer pence. The highest eligible quantity tier is used; fixed amounts apply per complete group, percentage savings apply to all eligible units, and packages occupy the highest-priced unclaimed units. Ties follow rule priority and UUID; the stackable result wins a tie against an exclusive result. Eligibility is by exact component/variant ID or category with explicit exclusions. Discounts never round a physical unit below one penny. Fixed/discount bundles, add-ons and measured sets are priced independently from ordinary component offers. The established UK delivery threshold is applied to net merchandise. A bounded, non-authorizing quote digest must match a fresh server reprice before an order or reservation can be created.

The existing Edge checkout endpoint still gates the store and uses validated account ownership, the existing Orders table, Stripe idempotency and Stripe line amounts from persisted trusted totals. Paid fulfilment still uses the signed webhook and existing stock transaction. Snapshot rows store the original/net prices, rule versions, components, add-on instructions and measured units; private costs are in a separately guarded Admin projection. Cost references are current at order time, nullable, and are not historical BLACK LEDGER restatements. Original Orders and financial records are never rewritten.

Inventory uses one shared stock source. A stock-row lock protects ordinary reservations, Admin measurement recording and aggregate stock updates. Measured units count against that floor and can belong to only one set. Set membership checks exact variant with a configurable full spread relative to the lowest measurement. The existing paid-order transaction consumes the reservations and deducts components once. Other existing stock writers cannot lower stock below the floor. Signed terminal Stripe expiry releases a reservation; browser cancel and elapsed local time do not prove Stripe expiry. Rolling back the storefront must not disable pay/expiry processing for existing reservations.

Configured wiring kits continue using their original checkout and pricing. They can reserve their validated physical requirements after the database gate is enabled. Mixing a configured kit with a Commerce-specific selection in a single commercial quote is currently unsupported; the interface asks for separate baskets. Ordinary old/mixed carts do not receive new discounts. The protected preview uses static fictional data only, with a deny-network CSP; it is a UI acceptance surface, not a live payment or hosted Supabase environment.

## Production cutover and rollback (separate approval)

1. Review and approve the exact migration checksum and guarded Cloudflare frontend/backend packages. Reconcile live schema and function definitions (the migration refuses unexpected legacy entry/fulfilment hooks). Exercise this on a recent sanitized clone and verify against deployed Admin policies.
2. Verify an abuse control for pending reservations, including guest floods, and bound reservation duration through Stripe. Establish a documented service-only reconciliation path for outcomes where Stripe may have created a session but attachment did not complete. Do not release such a hold from a browser, timeout, or missing local response alone.
3. On the isolated stack, verify signed Stripe expiry delivery, paid webhook/refund behavior and repeat delivery, mismatch and attachment recovery end to end using test mode. Verify legacy Orders, BLACK LEDGER and production-shaped Admin authentication. Verify current inventory/IRONCLAD write paths and that the operator can restore a saved configuration and reconcile physical labels. Record acceptance of the mixed-kit restriction before activation.
4. Back up schema and verify the current Cloudflare application rollback. Apply the additive migration with both runtime and storefront flags false. Deploy the compatible checkout and webhook code, configure confirmed expiry delivery and leave the feature off. Pause new checkout in a bounded maintenance window; drain or reconcile older unpaid Stripe sessions before enabling the stock floor for new reservations. Enable backend processing before guarded Cloudflare UI, then resume checkout and perform controlled verification.
5. On rollback, turn off new checkout and offer UI, use the last verified Cloudflare deployment and preserve the additive tables. Keep compatible paid/expiry webhook handling until every held checkout is reconciled. Never drop audit/snapshot data or blindly release a hold. A separately reviewed cleanup migration is only for a fully drained system.

This migration is prepared for review, never applied to a hosted database by this authorisation. Commerce activation is recommended only after the listed live boundary and reservation abuse tests pass.
