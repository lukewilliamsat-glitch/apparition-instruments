Authorisation 69 covers isolated engineering, the dedicated synthetic Supabase project and an Access-protected fictional preview. Production publication, Stripe, buyer communications and production data changes are out of scope. The accepted application parent is ECLIPSE `cc34aa5ae5326134dbc215af673b5132c45da29c`. ANCHOR remains an independent production recovery gate.

## Inventory and attribution

- Physical stock remains `public.inventory.quantity`. The current catalogue identities, fixed BOMs, configured kit choices, order fulfilment and existing cost references stay in place. IRONCLAD introduces no second physical stock counter.
- The workspace shows free availability after the existing Commerce holds, separate bench allocations and deliberate quality holds. Incoming is ordered but not received. None of those classifications is a physical deduction. Recommendations are not commitments.
- Tracking is enrolment driven. The first opening batch reflects the existing count with unknown cost. The trigger only tracks enrolled components; it records increases and decreases from existing writers as upstream events when no authorised IRONCLAD source exists. Fungible decreases use opening/adjustment then oldest receipts, consume free units and never claim proof of the physical batch. If an individually measured but unidentified unit is consumed, its measurement becomes retired rather than falsely attributed to an order.
- Receipts serialise by purchase and inventory row locks. Same request and body replay the original receipt; changing the same request is a conflict; repeat delivery references and excess quantities fail atomically. Purchase lines are fixed when created in this version: cancel unreceived purchases and make a new one if the draft needs changing. An order that has been partially received cannot be silently cancelled or reversed here.
- Shared GBP costs are allocated by quantity, actual converted merchandise value or explicit amounts. Cumulative rounding reconciles the total to exactly the entered amount. Partial receipt cost is the difference of cumulative apportioned totals. Estimated unit precision is not rounded to whole pence before use. Recoverable taxes are not included. No exchange rates or historical opening costs are invented.
- Bench measurements are entered sequentially in kΩ and stored as integer ohms. Compatibility is component identity, nominal ohms, taper and shaft. The narrowest full spread uses an exact rational comparison, resistance then stable unit ID for ties. Maximum sets uses earliest qualifying sorted windows within each exact compatibility group. A partial unique index enforces one active set per unit. Marks do not deduct quantity; dataset, quality or active set changes invalidate a captured stocktake.
- Bench allocation and quality holds are confined to isolated inactive components with no sellable, assembly, kit, unpaid-checkout or existing hold path. Catalogue relisting and assembly/kit linkage are blocked until protected bench stock is released. This preserves the existing sale flow; it does not make matched sets purchasable. Future Commerce work must choose one canonical unit registry, consume existing reservations against those units, model reservation disjointness and revalidate compatible set fulfilment. Do not run both allocation engines independently for the same stock.
- Historical cost capture checks the paid fulfilled order line, exact component, quantity and acquisition timing. The unique immutable order/line record retains the numerator and denominator. A verified physical trace requires explicit evidence; otherwise the allocated batch is an estimate for ECLIPSE, not proof of the lot sold. Import into an ECLIPSE draft is explicit and only populates unknown lines. Existing financial records and revisions are never updated by capture. Sets/assembly evidence, historical opening batch evidence import, discrepancy over-receipts, full-catalogue stocktake orchestration and machine-readable labels are future work. Use scoped stocktakes of up to 50 items and text ID label printing in this build.
