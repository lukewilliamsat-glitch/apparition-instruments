## Optimisation scenarios
- Independent static images: metadata body shrinks, but image asset downloads move to static hosting; cold asset bytes do not disappear. Browser reuse and source-identity parity need separate measurements.
- Lazy project dependencies: remove incidental catalogue/kit reads; residual actual commerce and matching calls remain.
- Admin summary/detail: reduce listing bytes, add selected-detail requests; preserve write-side validation and account for it.
- Static-only release: remove all backend generator calls only when every step is truly offline and complete deployment inputs are verified.
- Operations backoff: fewer failure-cycle requests, but purchasing safety and boundary refresh remain mandatory.

No probabilities or additive savings are invented. Current live usage, cache hit ratio, changed-image frequency and service-level attribution are unknown.
