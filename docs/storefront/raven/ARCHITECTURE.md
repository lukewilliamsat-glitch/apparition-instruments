## Data and startup dependency chain

Public component repository → `backend/catalogue-image-delivery.mjs` / `public-read.mjs`. Production static-image config remains **enabled:false**, so ordinary image-enabled reads retain the image-bearing projection. Public cache coalescing is bounded and URL/fetch-function scoped, not a universal single-read guarantee.

Components → catalogue top-level load; product app → catalogue and commerce; commerce → kit snapshot → Les Paul config → kit-data. In a browser kit-data eagerly loads components plus kit definitions/permissions. Knowledge/tool imports can reach this graph too. In ordinary Node source tests repository selectors use local in-memory seeds; those results cannot certify browser startup or network counts.

The Components try/catch starts **after imports**. Likewise startProductDetail's load catch and basket/checkout render catches cannot catch an earlier rejection of catalogue's top-level await. This is RAV01's exact failure boundary. The existing kit builder's dynamic adapter mount has a separate caught loading lifecycle; do not describe every builder path as equally unhandled.

`site.mjs` independently boots Operations on public shared headers, reads a local snapshot, then fresh store/announcement RPCs. It polls visible pages at 60 seconds plus time/visibility events, dispatches store status and keeps purchasing unavailable on failure. Commercial destinations are a further scoped public read; configured product handoff can use an image-free ID query. Preserve these independent business boundaries.

## Build/publication dependency

The unchanged Pages workflow triggers main pushes, manual dispatch and daily `0 3 * * *`. Normal generation reads catalogue + options concurrently, Operations + News concurrently, then CMS. CMS remains unconditional for `[static-only]`/`[cms-only]` pushes. Search-verification preparation, build-revision stamping and upload/deploy follow successful generation. No current workflow path is established as backend-free.
