# Prioritised improvement roadmap

**Recommendations only. No implementation starts from this document.** P0 = critical correctness/purchasing-state blocker; P1 = important usability/trust/conversion work; P2 = optional enhancement. Evidence levels are S (source), H (historical browser), L (likely concern), R (recommendation). Fresh browser reproduction is unavailable for every new candidate. Exact machine-readable source/evidence/dependency/security/acceptance fields are retained in [FINDINGS.json](FINDINGS.json).

Phases below are proposed engineering order, not authorisations: **1** purchasing-state feedback; **2** saved-intent/interaction recovery; **3** product/help content; **4** responsive/assets; **5** optional discovery/visual maintenance. Existing release candidates have their own gates and are not to be rewritten.

## Recommended first authorisation and owner decisions

Commission **Phase 1: honest purchasing-state feedback**, limited to RAV01 and RAV02 in a new candidate. Reproduce initial module failure and cross-page ordering copy with fictional records; provide genuine isolated browser acceptance when its prerequisites are available. Preserve inventory/pricing/checkout/Operations semantics and all frozen branches. This recommendation does not authorise execution or CI now.

Then review RAV03/RAV15/RAV06 as interaction recovery, with explicit persisted-intent/idempotency/focus invariants. Product facts/policies/claims need owner-approved evidence before RAV04/RAV10/RAV12. Asset/header work follows safe browser and physical-device access. Search/gallery/fonts are optional owner choices. HOMECOMING and NIGHTFALL retain independent release/infrastructure gates; no phase is bundled into “make the storefront premium”.
