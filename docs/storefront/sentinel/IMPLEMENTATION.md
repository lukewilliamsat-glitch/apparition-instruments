# Candidate changes

RAV03 (`a2bd49b5bda3247438f406c4762fd5514af986f2`): retain valid version-1 component identity and quantity even when the current in-memory catalogue cannot resolve it. Derive the unavailable marker from the current catalogue rather than trusting storage. Save only canonical component fields; reject malformed identity, unsupported quantities, unsafe SKU strings and duplicate IDs. Render saved references with text nodes, show an explicit Remove action, and omit unavailable price/stock claims. Block complete totals and checkout while any component remains unresolved. Normal quantity/stock checks and kit snapshots retain their original semantics.

RAV15 (`1efe94b18177530a41e5d82f0002b0c6f1fff3d4`, with feedback preservation in the acceptance commit): key checkout rendering to actual basket/shipping changes. Keep the mounted form on unchanged status events, update a separate accessible availability status, and disable it according to current Operations authority. A shared submission guard is established before the asynchronous account check. Pending requests retain the same controls and request identity. Basket changes defer reconstruction until the active attempt settles; a definite error survives that reconstruction. Late responses cannot initiate handoff after the basket or availability changes.

Ambiguous checkout transport/response failures produce a settled, disabled **Checkout outcome unconfirmed** control and explicit help guidance. Status events and repeated submission events do not start another application attempt. This hold lasts within the mounted document; it is not a new durable reconciliation protocol across page reloads. Definite rejection permits deliberate retry when OPEN, retaining the existing request identity.

RAV06 (`9bde44e500736d9958c3f571f6e40cd036fa361d`): set the form's `aria-busy` during the active attempt and clear it on settlement. An uncertain settled attempt keeps its existing duplicate guard and message but labels its disabled button **Delivery not confirmed**. Definitive failures restore Send enquiry; confirmed success retains the existing success flow. No automatic resend or endpoint detail is introduced.

Only four inherited frontend files change: `dist/commerce.mjs`, `dist/basket-ui.mjs`, `dist/checkout/checkout.mjs`, `dist/contact/contact.mjs`. Additional files are isolated SENTINEL tests, its exact-branch CI workflow and these reports. No dependencies were added beyond the already verified LIGHTHOUSE disposable test lock.
