## Architecture and implemented files

GitHub Pages is appropriate because it already hosts the public storefront and static assets. Supabase retains authoritative catalogue, inventory, prices and checkout. No new paid provider, secret, browser GitHub permission or production image rewrite is proposed.

`dist/backend/image-delivery-config.mjs` is hard-coded `enabled:false`. `catalogue-image-delivery.mjs` adds an opt-in image-free view projection, source-identity matching, bounded 30-second manifest/readiness caches, manifest revision validation, MIME/byte HEAD readiness checks and per-product legacy fallback. `component-data.mjs` and `providers.mjs` route public image-bearing reads through this adapter; the inactive path uses the exact original view/projection/cache. `public-read.mjs` allowlists only the proposed additional public view. Admin transport and repositories remain byte-for-byte unchanged.

`HEAD` establishes availability/MIME/length, not a cryptographic proof of live content. A future publisher must verify live GET bytes/hash before activation. If source identity changes, an old static entry cannot attach to the new record. Concurrent fallback identity changes result in a safe placeholder until fresh metadata. Existing HTTPS object references remain supported. Supabase catalogue failure fails closed rather than substituting stock/prices. New paths are never requested while disabled.

`scripts/catalogue-image-assets.mjs` is a pure planner/staging writer with no CLI, implicit network read or Actions wiring. Stable IDs bind source hashes to decoded content hashes. Exact source bytes are decoded without resizing/re-encoding; PNG/JPEG/WebP MIME/signatures and canonical base64 are checked. Deterministic manifest revision, deduplicated assets, immutable filenames, exact byte/hash verification, concurrent identical writers, atomic local manifest alias replacement, retained versioned manifests and old assets are fixture-tested. It performs no garbage collection.

Review-only `docs/approval/catalogue-delivery-v2.sql` creates a single invoker view. It is outside the migration directory and was not applied. `catalogue-image-publication-v2.md` specifies the separately approved trusted workflow, extraction, verification and cutover gates. The existing Pages workflow/generator are unchanged.

## Admin and publication design

Keep normal Admin add/upload/replace/remove/preview/save. Embedded source values remain intact throughout. A separately approved trusted Actions publisher compares lightweight source identities with the last verified manifest and fetches only changed product images; scheduled builds must reuse retained assets rather than download every image again. Review exact workflow/generator patch before deployment. Existing GITHUB_TOKEN scoped Actions artifact read and Pages deployment permissions should suffice; no repository write or browser publishing token. Preserve one Pages artifact/run and non-cancelling deployment concurrency. Existing 15-minute schedule plus queue/build/CDN latency applies.

Asset availability is confirmed before manifest references become active. Partial failure retains source images, old assets and manifest; matching source falls back only for the affected product. Prior-artifact availability/expiration is an explicit implementation gate. Generated SEO pages must later reuse the same references; this is not implemented under current infrastructure restrictions. A publication status UI/explicit publish control is not added in preparation. No owner routine GitHub edits are required by the proposed automated route.

Content hashes prevent indefinite stale URL reuse after replacement. Pages controls actual HTTP cache headers; this preparation cannot promise `immutable` or a one-year cache. Browser image HTTP cache reuse is independent of the 30-second metadata/readiness caches. Manifest alias fetch uses no-store. Keep all old assets until a separate retention/GC approval. Versioned manifest rollback is supported. Actual browser image network-cache reuse is pending an approved asset deployment and browser acceptance test.
